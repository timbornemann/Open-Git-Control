# Repository statistics and analytics

Open **Statistics & analytics** with its chart icon directly below **Local repositories** in the activity bar, **Ctrl+6**, a repository's context menu, repository actions or command palette. It is a standalone app page bound to the active repository, with its own sidebar for report navigation. The sidebar identifies the repository and lets you switch between open repositories through the normal activation flow. Unsaved file edits remain protected. The repository Git-action toolbar, external staging inspector and subpage back button are hidden here. The dashboard runs offline from existing Git objects. Shared filters live in the sidebar; only detailed report contents scroll. Overview fits the available page height. A saved report appears immediately on reopening, followed by a background refresh. Progress and cancellation use the app's notifications.

The sidebar contains shared history, date, person, path, time aggregation and project-tree filters. They apply across report sections and are saved per repository. Summary figures appear on one divided surface in **Overview**, while the sidebar opens detailed reports. Its active section also follows drilldowns on people, paths and periods; the selection is retained separately for each repository within the session. The six sections are Overview, Change hotspots, Contributions, Code Churn, File coupling and Release comparison. Commit history remains on **Current repository**. Overview divides the available height between metrics, activity, languages, hotspots and versions, without vertical page scrolling. Language previews adapt to the available space; **Show all types** opens the full grouped list if needed. Detailed reports still scroll. The report timestamp and refresh action sit beside **Statistics & analytics** in the main header, without a separate toolbar row. Background refreshes retain the displayed report, selected section, detail page and scroll position until updated results are ready.

Activity charts show commit counts above each bar and localized dates along the time axis, including inactive gaps. Date labels adapt to the chart width. Dense charts scroll horizontally to keep counts legible. Bars remain keyboard accessible and filter Contributions to the chosen period; Code Churn retains its own section when filtering. Activity has no additional chart-data table.

**Code Churn** fills the report's available height with a diverging chart: additions rise above a shared zero line and deletions extend below it, on the same labeled line-count scale. Four divided summary segments show additions, deletions, total changes and signed net change; a proportional strip shows the overall added/deleted shares. The complete timeline fits the available width, including inactive periods, without horizontal scrolling or changing the aggregation. Value labels adapt to the space and prioritize large changes; every period retains exact hover/focus details and keyboard navigation. Localized dates become more compact on narrow screens. Selecting a period keeps Code Churn active and applies the shared time filter. There is no duplicate chart-data table. Summary segments wrap on narrow screens, and short windows can scroll the report.

The activity calendar fills the available width with square day cells, localized month and weekday labels. On narrow screens its own viewport scrolls horizontally to preserve usable cell sizes. Each day exposes its date and commit count on hover and to assistive technology; there is no duplicate calendar table. Arrow keys move by day vertically and by week horizontally. Selecting a day filters Contributions to that date, and the selected year remains stable during background updates.

**Contributions** combines activity and **Last changed lines** in one contributor table; line attribution has no separate report page. Activity columns follow history filters, while line counts and shares describe the independently selected project tree. People who retain lines but have no commits in the filtered history remain visible with zero activity. The person filter limits displayed rows; shares still refer to all attributed lines in the project tree. Incomplete attribution is identified with coverage and unavailable counts are shown as a dash rather than zero. Existing session selections of the former line-attribution page open Contributions.

Change hotspots use a path-based treemap in both Overview and the detailed report, including directory grouping. Nested directory regions keep related paths together. Areas are allocated by change counts within each region; colors show frequency from cool low activity to warm high activity. Readable tiles show their name and count; all paths have accessible labels and hover/focus details. The color scale is relative to the most frequently changed path in the filtered report and stays consistent across detail pages. Hover or keyboard focus shows the full path, change count, contributors, line changes and last change. Clicking a file opens its captured historical version; clicking a directory filters Change hotspots to that path. Arrow keys move spatially through the map and Escape dismisses its tooltip. Overview previews the 48 most changed files; the detailed report keeps pagination. Frequency does not measure code complexity.

Languages and file types use a combined distribution strip and individual proportional bars, with file counts, line counts and localized percentages. The overview prefers a single column when its height accommodates all types; two columns are used only when space calls for them. Types with an individual share of **at most 0.1%** of text lines are combined as **Other**, preserving their combined file/line totals; its tooltip lists the included types. Shares refer to text lines; binary files, LFS, symlinks and submodules appear separately as file counts. CSS bar widths use unformatted numeric ratios regardless of the display locale. Notification percentages are rounded to whole values.

## Scope and definitions

The default history includes commits reachable from local and existing remote branches and an additional detached HEAD, once per object ID. Tags are version and comparison targets. Stashes, reflogs and internal app refs are excluded. Branch selection, author, path and local author-date filters control history reports; daily, weekly and monthly aggregation are available.

**Project tree** independently selects the committed version used for file counts, physical text lines and blame. Working files and staging never contribute. Text lines include comments and blank lines. Language/file type follows paths and extensions; unknown text formats remain visible. Binary files, LFS pointers, symlinks and submodules have separate file categories and do not contribute artificial text-line counts.

Merge commits count as activity, but merge diffs are not added to churn, change hotspots or coupling. **Change hotspots** measure how often paths change, not code complexity. **Last changed lines** uses standard blame without extra whitespace/copy detection and shows attribution coverage separately. Names and email addresses come from Git and the selected tree's `.mailmap`; matching names alone do not merge identities.

The selected tree's `.gitignore` rules additionally filter already tracked and historical paths for these reports. This differs from normal Git tracking behavior. Nested rules and negations follow Git's matching rules. Global ignores and `.git/info/exclude` do not change project analytics; total commit counts remain complete.

File coupling shows pairs changed together in at least three ordinary commits. Its percentage is shared commits divided by commits changing at least one path. Commits with more than 50 eligible files are omitted only from coupling and counted separately.

Release comparison displays newly reachable commits in `A..B` separately from the net tree diff `A → B`. Non-ancestor targets are explained. The default compares the newest reachable version tag with HEAD. Clicking a path opens its captured commit diff without checking it out; **Analyze** filters Change hotspots to that path.

## Local cache and incomplete results

The versioned `repository-analytics` cache lives in app data, outside the repository. It stores commit metadata, per-path counts, blob line counts, blame attribution and aggregates, never full file or patch contents. New commits receive new diff records; unchanged commit records are reused. Removed branches and rewritten history update membership without deleting reusable records. Blob identity reuses line counts. Linear changes rerun blame for touched paths, including changes later reverted; merges and rewrites require an appropriate blame snapshot or fresh attribution.

Ignore and mailmap changes reaggregate existing records. Git version, fixed diff options and relevant attributes determine cache validity. Snapshot publication is atomic; completed records survive interruption, and malformed records are skipped and recomputed. Cancelled calculations are not marked complete. Background Git reads yield to interactive operations and stop on repository changes.

No checkout, index changes, external diff programs, text conversion or lazy object downloads occur. Shallow clones explain their limited local history. Missing objects fail the affected calculation with technical details in the central notification; incomplete reports and blame coverage remain identifiable. No analytics operation adds Git or hosting write access to the local Planning API.
